# ADR 0001: 기능 중심 모듈형 모놀리스를 유지한다

- 상태: Accepted
- 날짜: 2026-07-16

## 맥락

서비스는 현재 하나의 Spring Boot 애플리케이션과 단일 데이터베이스로 실행된다. 작업 관리 기능은 아직 작고 배포·관측·보안 기반 기능을 함께 성숙시켜야 한다. 이 단계에서 서비스 경계를 먼저 분리하면 네트워크 계약, 배포, 데이터 일관성 비용이 제품 기능보다 커진다.

## 결정

하나의 배포 단위 안에서 기능별 패키지 경계를 둔 모듈형 모놀리스를 유지한다. `task`처럼 HTTP 계층, 애플리케이션 서비스, 저장소를 기능 단위로 함께 두고, 공통 HTTP 오류 처리와 관측성은 `common` 또는 `observability`에 둔다. 다른 기능의 엔티티나 저장소에 직접 의존해야 할 때는 먼저 서비스 경계를 통해 필요한 동작을 노출한다.

## 결과

- 로컬 개발과 통합 테스트가 단순하고 트랜잭션 일관성을 유지하기 쉽다.
- 기능 경계가 코드 구조에 남아 향후 분리가 필요한 시점에 의존성을 파악할 수 있다.
- 독립 확장·독립 배포가 필요해지면 이 결정을 재검토하고, 새 ADR에서 분리 대상과 데이터 소유권을 명시한다.

## 고려한 대안

- 처음부터 마이크로서비스로 분리: 현재 규모에서는 운영·계약·분산 데이터 비용이 과도하다.
- 계층별 전역 패키지 구조: 기능 하나를 변경할 때 관련 코드가 넓게 흩어져 경계가 약해진다.
