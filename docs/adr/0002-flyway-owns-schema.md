# ADR 0002: Flyway만 운영 스키마를 변경한다

- 상태: Accepted
- 날짜: 2026-07-16

## 맥락

JPA 엔티티는 애플리케이션 모델을 표현하지만, 운영 데이터베이스의 스키마 변경 이력과 안전한 업그레이드 절차까지 제공하지는 않는다. 서로 다른 환경에서 스키마가 달라지면 배포와 복구의 신뢰성이 낮아진다.

## 결정

운영 스키마는 버전 관리되는 Flyway 마이그레이션으로만 변경한다. Hibernate는 `validate` 모드로 실행해 엔티티와 적용된 스키마의 불일치를 조기에 감지한다. 이미 배포된 마이그레이션은 수정하지 않고, 모든 데이터·스키마 변경은 새 마이그레이션으로 추가한다.

## 결과

- 데이터베이스 변경의 순서와 이력이 코드 리뷰 및 배포 과정에서 명확해진다.
- 자동 DDL 생성으로 인한 환경별 차이를 피한다.
- 되돌리기나 대규모 데이터 이동은 별도 운영 절차와 검증을 요구할 수 있으며, 해당 절차는 필요한 변경의 ADR 또는 runbook에 기록한다.

## 고려한 대안

- Hibernate `update` 사용: 편리하지만 운영 변경 이력과 검증 가능한 업그레이드 경로를 제공하지 않는다.
- 수동 SQL 적용: 실행 순서와 적용 여부를 일관되게 추적하기 어렵다.
